# 首个受治理操作是语义目录变更而不是沙箱 MCP

首版审批链的第一个可执行操作由 Sandbox Work Tracker MCP 的 `create_follow_up_task` 改为**工作区语义目录（指标定义）的变更**：升级自定义口径为共享版本或修订标准口径。理由：目录变更有真实且可观察的内部后果（改变全工作区后续分析的含义），审批不是演示道具；执行器是纯 Java 内部逻辑，无需沙箱基础设施；`workspace_policy.requires_separate_approver` 策略维度天然承载审批严格度——宽松策略下管理员/分析师变更需经确认弹框自批（confirm-to-record：防误操作、留痕、公示），严格策略下自批被拒并要求另一合格审批人。业务用户与 Agent 只能创建升级提案（创建本身必须经发起者显式确认），共享目录的每次变更最终都由审批动作触发；参数不可变，修改即新提案。Tool Gateway 保持可插拔执行器设计，外部 MCP（含原 Sandbox Work Tracker）降级为后续可选执行器。本决定部分取代 0005 中"通过 MCP 执行"的首版落地形态，副作用必须经 Java 与人工审批的核心不变量不变。
