# AskMetric 12 周开发路线

## 约束

- 一名开发者，每周投入 15–20 小时。
- 一个 B2B SaaS 参考场景和一个 PostgreSQL 连接器。
- 一组已配置的模型与 Embedding Provider。
- 一个需要人工审批的语义目录变更操作（ADR-0009）。
- 每周都以可运行的纵向结果结束，不交付彼此断开的脚手架。

## 第 1 周：验证高风险边界

构建三个可执行技术探针：Java -> RocketMQ 5 -> Python -> RocketMQ 5 -> Java 双向链路、LangGraph PostgreSQL Checkpoint 恢复，以及确定性独立 HTML 渲染。锁定兼容的 Client 和容器版本。如果任一探针无法在开发机与 CI 中可靠运行，立即停止并修改架构，不能让后续业务功能依赖未经验证的链路。

验收：三个探针均可通过文档命令运行，且各有一个自动化 Smoke Check。

## 第 2 周：建立 Monorepo

创建 Vue、Spring Boot 和 Python 应用；建立版本化契约骨架、Docker Compose、格式化、Lint、测试、依赖锁、GitHub Actions、健康检查和本地配置示例。

验收：全新 Clone 无需模型凭据即可启动基础设施和三个健康应用。

## 第 3 周：身份与工作区隔离

集成 Keycloak，将身份映射为工作区成员关系，实现权限和工作区策略，加密数据连接 Secret，并应用和测试 PostgreSQL Row-level Security。

验收：跨工作区 API 和数据库测试可以证明数据隔离；演示工作区登录可用。

## 第 4 周：对话与持久运行

实现对话、消息、Agent 运行、分析任务、事件持久化、SSE 重放、停止控制和 Vue Chat 工作区。加入基础意图路由契约和确定性对话行为。

验收：问候会产生 Agent 运行但不创建任务；分析意图会创建任务；断线重连后可恢复可见时间线。

## 第 5 周：可靠的 Agent 调度

实现 Transactional Outbox 发布、RocketMQ Consumer、事件去重、Schema 兼容、重试/死信、取消和 Checkpoint 恢复。

验收：重复和乱序消息不会产生重复状态；Python 进程被终止后可以恢复任务。

## 第 6 周：分析基础

生成确定性的演示数据仓库和植入事件，实现语义目录 YAML 导入与版本管理、PostgreSQL 数据连接，以及 Java SQL AST 校验、数据分级、预算、执行和审计。

验收：经过授权的只读查询可以恢复已知植入事件事实；恶意 SQL 或超预算查询被拒绝。

## 第 7 周：有状态分析

实现有边界的 LangGraph 工作流、结构化意图路由、澄清、上下文包构建、指标选择、SQL 修正循环、证据快照和结构化进度事件。

验收：一条多轮 MRR 调查在完成澄清和下钻后产出可验证结构化结果。

## 第 8 周：知识与记忆

实现 MinIO 上传、文本型 PDF/Markdown/纯文本异步摄取、pgvector/全文混合检索、引用、对话摘要，以及需要用户确认且支持查看/删除的用户记忆。

验收：分析能够引用正确的工作区知识来源；注入文本无法改变策略；删除的记忆不会再次使用。

## 第 9 周：人工审批的受治理操作

实现操作提案、审批策略、分离审批人规则、Java Tool Gateway 幂等执行；首个执行器为语义目录变更（升级/修订指标口径），外部 MCP 执行器可选。

验收：已批准的后续任务只创建一次；被拒绝、被修改、被重放或未授权的提案不会产生副作用。

## 第 10 周：可审计 HTML 报告

完成可审计分析 Schema、表格/折线/柱状图表模型、确定性 HTML 模板、不可变版本关联、Report 工作区、下载审计和报告安全测试。

验收：一条完整分析可以生成离线可读的 HTML 报告，并能够仅根据持久化结构化数据逐字节重新生成。

## 第 11 周：评测与运维

创建至少 10 个成功评测用例和 5 个安全/失败用例，实现确定性评分、固定 Judge 评测、失败分类、OpenTelemetry 关联、成本/延迟预算、Operations 页面和故障演练。

验收：仓库公开一份版本化评测结果，失败均按阶段分类，并提供覆盖一条完整分析的 Trace。

## 第 12 周：公开证明

部署受限流保护的演示工作区，演练备份恢复和每日重置，校准 P95 表现，完善中英文 README，记录已知失败，并录制一条 3–5 分钟端到端演示视频。

验收：评审者可以打开 Demo、重现参考任务、检查对应 Trace 和 HTML 报告，并与公开评测结果对照。

## 完成定义

只有当用户链路可用、授权已执行、失败行为明确、相关遥测存在，并且最小有效自动化测试通过时，一个功能才算完成。依赖模型的行为还必须有评测用例。只有配置或只有 UI 的占位实现不算完成。

项目首版完成必须满足：

- 10 个核心分析用例中至少 8 个得到正确且带引用的结果；
- 展示多轮澄清、中断、审批和恢复；
- Java、Python 和 Vue 各自拥有不可替代的行为；
- 无需修改 Agent 工作流代码即可导入新的语义数据集；
- 没有模型凭据也能运行确定性测试；
- 公开 Demo、HTML 报告、Trace、成本、评测结果和已知失败均可访问。

## 延期裁剪顺序

如果进度落后，依次将演示数据仓库从百万级缩减到十万级、把语义目录编辑限制为 YAML 导入和只读页面、只支持表格/折线/柱状图、使用现成 Trace UI，并且只保留语义目录变更执行器。

不能裁剪多轮状态、Java/Python 所有权、工作区隔离、受治理 SQL、带引用 RAG、显式记忆、审批、评测或公开部署；这些能力共同构成求职证明。

## 风险门槛

| 风险 | 验证门槛与应对 |
| --- | --- |
| RocketMQ Python 兼容性 | 第 1 周完成双向容器探针；失败时在开发功能前更换传输方案 |
| RLS 与 Java 连接池 | 第 3 周完成跨租户集成测试和事务级工作区上下文 |
| Agent 成本或延迟失控 | 从第一条依赖模型的纵向链路开始设置单次运行预算 |
| SQL 或源数据泄漏 | Java 独占凭据、AST 校验、数据分级测试和结果限制 |
| RAG Prompt Injection | 知识来源发布前通过对抗性摄取用例 |
| 公开 Demo 滥用 | 合成数据、禁止外部连接和上传、配额及每日重置 |
| 报告不可重现 | 以结构化分析和证据快照为事实来源，确定性生成 HTML |
